# 第一次回饋

## compose healthcheck 不要依賴 wget

### 問題

原本 `serve` 的 healthcheck 是：

```yaml
test: ["CMD", "wget", "-q", "-O", "/dev/null", "http://localhost:8080/todos-summary"]
```

`wget` 不一定存在於 image 裡（目前 `alpine` 剛好由 busybox 提供，換成 distroless / scratch 就沒有），healthcheck 會因為找不到執行檔而永遠失敗。應盡量用原生指令。

### 選項比較

| 做法 | 能檢查什麼 | 依賴 | 備註 |
|---|---|---|---|
| `wget` / `curl` | HTTP 狀態碼 | wget / curl | alpine 的 wget 是 busybox 內建，curl 要另外裝 |
| `nc -z localhost 8080` | port 是否在監聽 | nc | alpine busybox 有，distroless 沒有 |
| `bash -c 'echo > /dev/tcp/localhost/8080'` | port 是否能連線 | bash | `/dev/tcp` 是 bash 內建功能，不是真實檔案 |
| binary 內建 `healthcheck` 子命令 | HTTP 狀態碼 | 無 | 最穩，要多寫 Go 程式 |

### 採用做法

改用 bash 的 `/dev/tcp`：

```yaml
healthcheck:
  test: ["CMD", "bash", "-c", "echo > /dev/tcp/localhost/8080"]
```

原理：bash 對 `/dev/tcp/<host>/<port>` 做重導向時會嘗試建立 TCP 連線，連得上回傳 0，連不上回傳非 0，compose 以此判斷 healthy。

### 注意事項

- **必須明確用 `bash -c`**。`/dev/tcp` 是 bash 的功能，不是檔案，busybox `sh`（ash）不支援。
- **alpine 預設沒有 bash**，所以 `Dockerfile` 加了一行 `RUN apk add --no-cache bash`。換成 debian / ubuntu 系 base image 則不用裝。
- 這只能證明 **port 有在監聽**，不能證明 app 正常回應（例如 app 卡死但 socket 還開著，仍會顯示 healthy）。若要檢查 HTTP 狀態，需改用 binary 內建的 `healthcheck` 子命令。
- 已修改：`docker-compose.yaml`、`docker-compose.local.yaml`、`Dockerfile`。
