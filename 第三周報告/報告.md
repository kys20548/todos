# 第三周報告

## 總覽

todo 專案容器化，並部署到第二周的兩台 VM：

| 機器 | 內網 IP | 跑什麼 | compose 檔 |
|---|---|---|---|
| devbox（內網機，離線） | `10.140.0.29` | 只有 PostgreSQL | `deploy/db/docker-compose.yaml` |
| jump（跳板機） | `10.140.0.28` | `migrate` / `serve` / `worker` | `docker-compose.yaml` |

- 程式合併成單一 binary `todoapp`，三個子命令：`migrate`、`serve --port 8080`、`worker event`，共用同一個 image，靠 compose 的 `command` 區分。
- `migrate` 是獨立的一次性指令（`restart: "no"`），不寫進 `serve` 的啟動流程。
- 每次 `docker compose up -d` 之前，image 要先在該機器 `docker load` 完成（兩台都沒有 build 環境，devbox 還沒有外網）。

## 一、devbox：只跑 PostgreSQL

### 1. 準備離線 image 並上傳

```bash
mkdir -p dist
docker save -o dist/postgres-image.tar postgres:16-alpine
ssh devbox 'mkdir -p ~/todoapp-db'
scp dist/postgres-image.tar deploy/db/docker-compose.yaml .env.example devbox:~/todoapp-db/
```

`devbox` 這個別名透過 jump 轉送（`ProxyJump`），devbox 本身不需要外網。

### 2. devbox：載入 image、設定、啟動

```bash
cd ~/todoapp-db
docker load -i postgres-image.tar
cp .env.example .env && chmod 600 .env
```

`.env` 只保留 devbox 需要的幾行：

```
POSTGRES_USER=root
POSTGRES_PASSWORD=<密碼>
POSTGRES_DB=todoapp
DB_BIND_IP=10.140.0.29
```

```bash
docker compose up -d
docker compose ps
```

預期 `healthy`，且 ports 欄為 `10.140.0.29:5432->5432/tcp`。

### 3. 關於 `ports` 的寫法（重點）

```yaml
ports:
  - "${DB_BIND_IP:-10.140.0.29}:5432:5432"
```

格式是「host 綁定位址 : host port : 容器 port」。**最前面的 IP 是這台機器（devbox）自己的網卡，不是允許連進來的來源 IP**。

| 寫法 | 效果 |
|---|---|
| `10.140.0.29:5432:5432` | 只在 devbox 的內網網卡監聽，jump 連得到。本專案採用 |
| `127.0.0.1:5432:5432`（localhost） | 只有 devbox 本機連得到，jump 會 `Connection refused`，**不能用** |
| `5432:5432`（不寫，等同 `0.0.0.0`） | devbox 所有網卡都監聽，可用，但暴露面較大 |

另外：
- Docker 發佈 port 是自己改 iptables，會繞過 `ufw`，所以限制來源要靠 GCP 防火牆規則（只允許 jump 的內網 IP 連 5432）或 `pg_hba.conf`。
- 連通性檢查（在 jump 上）：`nc -zv -w 3 10.140.0.29 5432`。db 還沒起來時回 `Connection refused` 代表網路與防火牆是通的，只是沒人在聽；`timed out` 才是被防火牆擋住。

## 二、jump：跑 migrate / serve / worker

### 1. 準備離線 image 並上傳（本機）

```bash
mkdir -p dist
docker save -o dist/todoapp-image.tar todoapp:1.0
ssh jump 'mkdir -p ~/todoapp'
scp dist/todoapp-image.tar docker-compose.yaml .env.example jump:~/todoapp/
```

### 2. jump：載入 image、設定、啟動

```bash
cd ~/todoapp
docker load -i todoapp-image.tar
cp .env.example .env && chmod 600 .env
```

`.env` 只保留 jump 需要的兩行，**`DB_SOURCE` 的主機要改成 devbox 的內網 IP**，密碼與 devbox 的 `POSTGRES_PASSWORD` 相同：

```
DB_SOURCE=postgresql://root:<密碼>@10.140.0.29:5432/todoapp?sslmode=disable
APP_ENV=prod
```

為什麼不能寫 `db` 或 `localhost`：
- 跨機器時沒有 compose 的服務名稱解析，要寫對方的內網 IP。
- 容器內的 `localhost` 是容器自己，不是 jump。

```bash
nc -zv -w 3 10.140.0.29 5432        # 先確認連得到 db
docker compose up -d
docker compose ps -a
curl -s localhost:8080/todos-summary
```

預期：`migrate` 是 `Exited (0)`，`serve` 是 `healthy`，`worker` 是 `Up`。

### 3. 驗證兩邊打通

本機開通道看網頁：

```bash
ssh -N -L 8080:localhost:8080 jump
```

瀏覽器開 `http://localhost:8080` 新增一筆 todo，再到 devbox 確認資料真的在 db 裡：

```bash
docker exec todoapp_db psql -U root -d todoapp -c "select id,title from todos"
```

### 4. 注意事項

- **重建 db 後要在 jump 重跑 migrate**：db 容器只負責提供空資料庫，表是 migrate 建的，devbox 沒有 todoapp image，所以由 jump 負責：
  ```bash
  cd ~/todoapp
  docker compose run --rm migrate
  ```
- `docker compose` 的專案名稱取自執行時所在的資料夾名稱，請固定在 `~/todoapp` 底下執行，否則容器與網路的名稱會不一樣。

## 三、rootless docker 離線安裝步驟（jump）

使用跟 rootful 相同的六個 `.deb`（版本需一致）：`containerd.io`、`docker-ce`、`docker-ce-cli`、`docker-ce-rootless-extras`、`docker-compose-plugin`、`docker-buildx-plugin`。rootful 與 rootless 共用這一批套件，差別只在 daemon 怎麼啟動。

### 1. 安裝前置套件

```bash
sudo apt-get install -y uidmap slirp4netns
grep "^$(whoami):" /etc/subuid /etc/subgid     # 應有 danny:165536:65536 之類的條目
stat -fc %T /sys/fs/cgroup                     # 應為 cgroup2fs
```

- `uidmap` 提供 `newuidmap` / `newgidmap`，沒有的話安裝程式會直接報錯。
- `slirp4netns` 提供使用者空間網路，三者（slirp4netns / pasta / vpnkit）都沒有的話 daemon 啟動時會失敗。
- 沒有 subuid 條目時：`sudo usermod --add-subuids 100000-165535 --add-subgids 100000-165535 <使用者>`。

### 2. 安裝 deb 並關閉系統層 daemon

```bash
sudo dpkg -i ./*.deb       # 一次全部安裝，dpkg 會自己處理順序
```

安裝 `docker-ce` 會自動啟動 root 的 daemon，要停掉，否則會跟 rootless 混用：

```bash
sudo systemctl disable --now docker.service docker.socket
sudo rm -f /var/run/docker.sock
```

### 3. 以一般使用者身分安裝（不要用 sudo）

```bash
dockerd-rootless-setuptool.sh install
```

### 4. 設定 DOCKER_HOST

```bash
echo 'export DOCKER_HOST=unix:///run/user/$(id -u)/docker.sock' >> ~/.bashrc
source ~/.bashrc
```

### 5. 登出後繼續執行、開機自動啟動

```bash
sudo loginctl enable-linger $(whoami)
systemctl --user enable --now docker
```

### 6. 驗證

```bash
docker info | grep -iE 'rootless|cgroup version|Docker Root Dir'
docker compose version
ps -o user,pid,cmd -C dockerd
```

本次實測：
- `docker info` 出現 `rootless`，`Docker Root Dir` 是 `/home/danny/.local/share/docker`。
- `dockerd` 的使用者是 `danny`，不是 root。
- `No cpuset / io.weight / io.max support` 的警告只代表 rootless 下無法使用這幾種資源限制選項，本專案用不到。

### 7. 載入 image 並部署

rootless 有自己獨立的 image 儲存區，要重新載入：

```bash
cd ~/todoapp
docker load -i todoapp-image.tar
docker compose up -d
```

### 8. 疑難排解

| 現象 | 原因 | 處理 |
|---|---|---|
| `Missing system requirements ... uidmap` | 沒有 `newuidmap` | `sudo apt-get install -y uidmap` |
| daemon 啟動失敗，日誌寫 `One of slirp4netns, pasta, or vpnkit needs to be installed` | 沒有使用者空間網路元件 | `sudo apt-get install -y slirp4netns` |
| 修好套件後仍起不來，systemd 顯示 `Start request repeated too quickly` | 已被 systemd 限流 | 先清掉半成品再重裝：`dockerd-rootless-setuptool.sh uninstall -f`、`rootlesskit rm -rf ~/.local/share/docker`、`systemctl --user reset-failed`，再重新 `install` |

### 9. rootless 防住了什麼（對照實驗）

背景：**容器的 uid 只是 host 上 uid 的另一個名字，由 `uid_map` 翻譯**。

| 模式 | 容器內 uid | 逃出後在 host 上的身分 |
|---|---|---|
| rootful | 0 | root |
| rootful | 10001 | uid 10001，無權限 |
| rootless | 0 | 啟動 daemon 的使用者（danny，uid 1001） |
| rootless | 10001 | subuid 範圍內的 uid（165536 + 10000 = 175536），無權限、無帳號 |

rootless 把 daemon 本身降權，所以即使容器內是 root，逃出去也只是一般使用者。rootful 要達到類似效果，必須靠 image 的 `USER` 指定非 root。兩者是疊加的，不是二選一。

實驗（jump，rootless）：

```bash
# a. 容器內 root / app 在 host 上的身分
docker run -d --name t0 --user 0 --entrypoint sleep todoapp:1.0 999
docker run -d --name t1 --entrypoint sleep todoapp:1.0 999
ps -eo user,uid,pid,cmd | grep "sleep 999" | grep -v grep

# b. uid 對映表
cat /proc/$(docker inspect -f '{{.State.Pid}}' t0)/uid_map

# c. 模擬逃逸：容器內 root 去寫 host 的 /etc
docker run --rm --user 0 -v /etc:/host-etc --entrypoint sh todoapp:1.0 -c 'echo x > /host-etc/escape-test'
ls -l /etc/escape-test

# d. rootless 的代價：綁小於 1024 的 port
docker run --rm -p 80:8080 todoapp:1.0

docker rm -f t0 t1
```

實測結果：
- **c.** `/etc/escape-test` 不存在（`No such file or directory`），寫入被擋下。
- **a / b / d.** 預期 t0 為 `danny 1001`、t1 為 `175536`、`uid_map` 為 `0 1001 1` 與 `1 165536 65536`、綁 80 失敗。（實測輸出待補）

對照組（devbox，rootful）用同樣的 c 實驗，預期寫入成功且檔案屬於 root；做完要 `sudo rm /etc/escape-test`。

rootless 的代價：
- 不能綁小於 1024 的 port（除非調整 sysctl）。
- 網路經由使用者空間轉送（slirp4netns），效能較差。
- 需要 cgroup v2 與 `/etc/subuid` 設定。
- 部分資源限制選項（cpuset、io 控制）不支援。

## 四、自我檢查

### a. image 大小是幾 MB，為什麼

`todoapp:1.0` 約 **50.7MB**（內容 13.8MB）。

原因是多階段建置：第一階段（`golang:1.27-alpine`）負責編譯，包含 Go 編譯器、套件快取與原始碼；第二階段只從第一階段複製編譯好的靜態執行檔、設定檔與前端檔案，放進乾淨的 alpine（約 8MB）。第一階段的所有層不會進最終 image。

對照：同樣的程式用單階段建置，大小為 **1.38GB**。

| 單階段的層 | 大小 |
|---|---|
| `go build` 產物與快取 | 346MB |
| `go mod download`（第三方套件） | 234MB |
| `COPY . .`（原始碼） | 131MB |
| `golang:1.27-alpine` 基底（編譯器與工具鏈） | 其餘約 670MB |

執行時只需要那支約 13MB 的執行檔，其他都是建置時才需要的東西。再加上 `-trimpath -ldflags="-s -w"` 拿掉路徑與除錯符號，進一步縮小。

### b. compose 停掉再起，資料還在嗎

- `docker compose down` 再 `up -d`：**資料還在**，資料存在 named volume，`down` 只刪容器與網路。
- `docker compose down -v` 再 `up -d`：**資料不見**，`-v` 會連 named volume 一起刪，重新建立的是一個全新的空資料庫。

實測（devbox）：`down -v` 之後資料庫整個消失，而且沒有表。因為表是 `migrate` 建的、而 migrate 在 jump，所以要到 jump 重跑：

```bash
cd ~/todoapp
docker compose run --rm migrate
```

這也說明：資料庫與資料表結構是兩件事，db 容器只提供空資料庫；migrate 是獨立的一次性指令，重建 db 之後要明確重跑，不能期待 serve 啟動時自動處理。

### c. 環境變數有好幾個地方都設了，跑起來用的是哪一個，怎麼證明

`DB_SOURCE` 出現的位置：image 內的 `config/app.prod.env`（`localhost:5432`）、jump 的 `.env`（`10.140.0.29:5432`）、shell 環境變數、compose 的 `environment:`。

優先序分兩段：

1. compose 取值：shell 環境變數 > `.env` 檔 > `${VAR:-預設值}`。
2. 容器內的程式（viper 的 `AutomaticEnv`）：環境變數 > `config/app.<env>.env` 設定檔。

所以實際生效的是 jump 的 `.env` 值，image 裡的 `localhost` 被蓋掉。

證明要分三層，缺一不可：

| 層 | 證據 | 指令 |
|---|---|---|
| compose 給了容器什麼 | 解析後的設定 | `docker compose config` |
| 容器裡實際有什麼 | 執行中容器的環境變數 | `docker compose exec serve env` |
| 程式實際用了什麼 | 真的連到哪裡 | `docker compose exec serve netstat -tn` |

實測：
- `docker compose config`：`migrate`、`serve`、`worker` 三個服務的 `DB_SOURCE` 都是 `...@10.140.0.29:5432/todoapp...`（另有一行是 `x-app` 錨點本身）。
- `docker compose exec serve netstat -tn`：serve 容器（`172.18.0.2`）有兩條 `ESTABLISHED` 連線到 `10.140.0.29:5432`（gorm 的連線池）。如果程式用的是設定檔的 `localhost`，就不會連到 devbox。

注意：`docker compose config` 只代表「compose 打算傳給容器的值」，不代表程式最終吃到的值；容器若是用舊設定啟動的，`config` 顯示的是新值，兩者可能不一致，所以後兩層不能省。輸出包含密碼，貼到文件前要遮掉。
