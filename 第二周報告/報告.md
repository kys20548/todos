# 第二周報告

## 第一題：本地 todoapp 連到雲端 VM 的 Postgres

### 做法

1. 本地開 SSH 正向通道，把本地 5432 轉到 VM 的 5432（視窗保持開著）：

   ```bash
   ssh -N -L 5432:localhost:5432 devbox
   ```

2. 關閉本地的 Postgres（避免 5432 被本地資料庫佔住），再開啟本地 todoapp。此時 todoapp 連 `localhost:5432` 實際上連到的是 VM 上的資料庫。

### 驗證

1. 在 VM 上進入 Postgres 容器，新增一筆 todo：

   ```bash
   docker exec -it todoapp_db psql -U root -d todoapp
   ```

   ```sql
   INSERT INTO todos (title) VALUES ('雲端建立-1');
   ```

2. 打開本地 todoapp 網頁，看得到「雲端建立-1」即代表成功。

## 第二題：雲端 VM 的 todoapp 連到本地的 Postgres

### 做法

1. 關閉 VM 上的資料庫，只留本地的 Postgres。

2. VM：允許反向通道綁在非 localhost 的位址（只要做一次）：

   ```bash
   ip addr show docker0 | grep inet        # 通常是 172.17.0.1
   sudo sed -i 's/^#\?GatewayPorts.*/GatewayPorts clientspecified/' /etc/ssh/sshd_config
   grep GatewayPorts /etc/ssh/sshd_config  # 確認有這行；沒有的話手動加上 GatewayPorts clientspecified
   sudo systemctl restart ssh
   ```

   原因：反向通道預設只綁在 VM 的 `127.0.0.1`，VM 上的 todoapp 跑在容器裡，容器內的 `localhost` 是容器自己，連不到。改綁到 docker0 的 `172.17.0.1`，容器才能透過這個位址連進通道。

3. 本地：開反向轉發，把 VM 的 `172.17.0.1:5432` 轉回本地的 5432（視窗保持開著）：

   ```bash
   ssh -N -R 172.17.0.1:5432:localhost:5432 devbox
   ```

4. VM：確認 port 有開：

   ```bash
   ss -ltn | grep 5432
   ```

5. 本地再開一條 8080 的正向通道，用來在本地瀏覽器打開 VM 上 todoapp 的網頁確認：

   ```bash
   ssh -N -L 8080:localhost:8080 devbox
   ```

### 驗證

在本地 Postgres 新增一筆 todo，接著透過 `http://localhost:8080` 打開 VM 上的 todoapp，看得到該筆資料即代表成功。

## 第三題：建立 demo01~03，只能用 SSH 金鑰登入

### 做法

1. 本地：產生一把模擬同仁的金鑰（`-f` 另取檔名，避免覆蓋自己的 `id_ed25519`）：

   ```powershell
   ssh-keygen -t ed25519 -f \Users\kys20\.ssh\colleague_test -C "colleague-test"
   ```

   私鑰 `colleague_test` 留在本地，當成同仁手上的鑰匙；公鑰 `colleague_test.pub` 要放到 VM。

2. 本地：把公鑰傳到 VM，存成公鑰清單（一行一把，之後有真的同仁公鑰就往裡面加）：

   ```powershell
   scp \Users\kys20\.ssh\colleague_test.pub devbox:~/keys.txt
   ```

3. VM：建立三個使用者並鎖住密碼：

   ```bash
   for u in demo01 demo02 demo03; do
     sudo useradd -m -s /bin/bash "$u"   # -m 建家目錄 /home/$u，-s 指定登入 shell
     sudo passwd -l "$u"                 # 鎖住密碼，就算 sshd 設定漏了也無法用密碼登入
   done
   getent passwd demo01 demo02 demo03    # 確認建立成功
   ```

4. VM：建立 `.ssh` 資料夾和 `authorized_keys`，並校正權限：

   ```bash
   for u in demo01 demo02 demo03; do
     sudo install -d -m 700 -o "$u" -g "$u" /home/$u/.ssh           # 建 .ssh 資料夾，權限 700，owner 是該使用者
     sudo tee /home/$u/.ssh/authorized_keys < ~/keys.txt >/dev/null  # 寫入公鑰清單
     sudo chown "$u:$u" /home/$u/.ssh/authorized_keys                # tee 由 sudo 執行，檔案 owner 會是 root，要改回來
     sudo chmod 600 /home/$u/.ssh/authorized_keys
   done
   sudo ls -la /home/demo01/.ssh         # 確認權限與 owner
   ```

   權限不對 sshd 會拒絕使用這把 key：

   | 位置 | 類型 | 常見值 | 為什麼 |
   |---|---|---|---|
   | 家目錄 | 目錄 | 755 / 750 | 可能要讓別人穿過（x）；只要別人不能寫就好 |
   | `.ssh` | 目錄 | 700 | 目錄要有 x 才進得去；裡面可能有私鑰，完全不給別人 |
   | `authorized_keys` | 檔案 | 600 | 檔案不需要 x；別人絕對不能寫，否則能塞公鑰冒充 |

5. VM：確認 sshd 已關閉密碼登入（GCP 的 Ubuntu 映像檔通常預設就是關閉的）：

   ```bash
   sudo sshd -T | grep -Ei 'passwordauth|kbdinteractive|pubkeyauth'
   ```

   期望：`passwordauthentication no`、`kbdinteractiveauthentication no`、`pubkeyauthentication yes`。

### 驗證

1. 用模擬同仁的金鑰登入，應該成功，登入後 `whoami` 顯示對應的使用者（demo02、demo03 同理）：

   ```powershell
   ssh -i \Users\kys20\.ssh\colleague_test -J danny@35.201.136.42 demo01@10.140.0.29
   ```

2. 改用自己的金鑰登入 demo01，應該失敗（自己的公鑰不在 demo01 的 `authorized_keys` 裡）：

   ```powershell
   ssh -i \Users\kys20\.ssh\id_ed25519 -J danny@35.201.136.42 demo01@10.140.0.29
   ```

## 第四題：/data 資料夾依使用者限制存取

### 背景觀念

- **Linux 權限只有 owner / group / others 三組**：一個資料夾只能指定一個 group，所以「兩個人能進、其他人不能進」的做法是建立一個只有這兩人的 group，把資料夾的 group 設成它，others 設成沒權限。
- **權限數字的意思**：三位數依序是 owner、group、others，每一位由 r=4、w=2、x=1 相加，7 是 rwx 全開，0 是全關。

  | 權限 | owner | group | others | 結果 |
  |---|---|---|---|---|
  | 700 | rwx | --- | --- | 只有 owner 能進 |
  | 770 | rwx | rwx | --- | owner 和 group 成員能進 |

- **每個資料夾對應一個 group**：

  | 資料夾 | owner:group | 權限 | 誰能進 |
  |---|---|---|---|
  | folder_01 | demo01:demo01 | 700 | 只有 demo01（owner） |
  | folder_012 | root:g012 | 2770 | g012 成員：demo01、demo02 |
  | folder_013 | root:g013 | 2770 | g013 成員：demo01、demo03 |

- **folder_01 為什麼不用另建 group**：只有一個人，直接用 owner 權限 700 就好。
- **2770 的 2 是 setgid**：資料夾設 setgid 之後，在裡面新建的檔案 group 會自動繼承資料夾的 group（g012），而不是建立者自己的 group。不設的話，demo02 建的檔案 group 是 demo02，demo01 可能改不到。
- **群組變更要重新登入才生效**：`usermod -aG` 之後，已經登入的 session 還是舊的群組，要登出再登入。
- **root / sudo 不受限**：root 會略過一般檔案權限，danny 用 `sudo` 一樣能進去。題目的「其他人」指的是一般使用者；danny 不加 sudo 就會被擋。

### 做法

1. 建立 group 並加入成員：

   ```bash
   sudo groupadd g012
   sudo groupadd g013
   sudo usermod -aG g012,g013 demo01   # -a 是附加，沒有 -a 會把原本的附加群組清掉
   sudo usermod -aG g012 demo02
   sudo usermod -aG g013 demo03
   ```

   確認：`id demo01 demo02 demo03`

2. 建立資料夾並設定權限：

   ```bash
   sudo install -d -m 755 -o root -g root /data                    # /data 本身讓大家能穿過，但不能寫
   sudo install -d -m 700  -o demo01 -g demo01 /data/folder_01
   sudo install -d -m 2770 -o root   -g g012   /data/folder_012
   sudo install -d -m 2770 -o root   -g g013   /data/folder_013
   ```

   確認：`ls -la /data`，期望看到：

   ```
   drwx------  demo01 demo01  folder_01
   drwxrws---  root   g012    folder_012
   drwxrws---  root   g013    folder_013
   ```

   （`s` 出現在 group 的 x 位置，代表 setgid 有設上）

## 第五題：在 demo01 家目錄建立三個資料夾的捷徑

### 做法

以 demo01 的身分建立捷徑（symlink），這樣捷徑的 owner 一開始就是 demo01：

```bash
sudo -u demo01 ln -s /data/folder_01 /home/demo01/folder_01
sudo -u demo01 ln -s /data/folder_012 /home/demo01/folder_012
sudo -u demo01 ln -s /data/folder_013 /home/demo01/folder_013
```

確認：`sudo ls -al /home/demo01/`，應看到三個 `folder_xx -> /data/folder_xx`，owner 為 demo01。

- `ln -s 目標 捷徑位置`：建立 symlink，內容只是一個指向目標的路徑。
- `sudo -u demo01`：danny 沒有權限寫 demo01 的家目錄（750），但 demo01 自己可以，所以用 demo01 的身分執行。
- 捷徑的 owner 其實不影響權限：透過捷徑存取時，Linux 檢查的是目標資料夾的權限，捷徑本身的 owner 和權限都不看。第四題權限設對，第五題就不用另外處理權限。設成 demo01 只是讓 owner 一致，屬於整理性質。

### 遇到的問題：chown -h 沒有生效

一開始的做法是先用 sudo 建立捷徑，再用 chown 把 owner 改成 demo01：

```bash
sudo ln -s /data/folder_01 /home/demo01/folder_01
sudo chown -h demo01:demo01 /home/demo01/folder_01   # -h 改 symlink 本身的 owner，不是改目標
```

chown 執行後沒有報錯，但 `ls -al` 看到捷徑的 owner 仍是 root。

推測原因：Ubuntu 25.10 之後，`chown`、`ls` 這類基本指令預設改用 Rust 重寫的版本（uutils），部分行為和原本的 GNU 版不一致，`chown -h` 改捷徑可能是其中之一。可用以下指令確認：

```bash
chown --version | head -1    # 顯示 uutils 就是這個原因；GNU 版會顯示 (GNU coreutils)
```

解法：先刪掉 root 建的捷徑（`sudo rm /home/demo01/folder_01`，rm 捷徑只刪捷徑本身，不會動到 `/data` 的資料夾），再改用上面 `sudo -u demo01 ln -s` 的做法重建，不需要 chown。
