# Go todo 專案

主題：檔案配置、錯誤處理、錯誤代碼定義、維運日誌、錯誤排查。

## 內容

寫一個 todo 的 Go 後端，並改一個現成的前端串接你的 API。

不給規格。照你自己對「一個完整的 todo 專案」的想像去做：功能範圍、資料設計、API 怎麼切、錯誤怎麼分類，你決定。

這個專案之後會一直用：02 搬資料庫、03 容器化、06 練 git。

## 提供

- Go 1.27 以上
- `pkg/results`、`pkg/builds`、`pkg/logging`：直接用，不重寫

前端二選一，選了不換：[todomvc](https://github.com/tastejs/todomvc)、[TodoApp](https://github.com/maciekt07/TodoApp)。後者原本是純前端儲存，改成打 API 的工作量不小。

## 硬性條件

- PostgreSQL，以 docker compose 啟動
- 前端能完整操作 todo
- 指導員照你寫的 README 能在他機器上跑起來

除此之外沒有規範文件。怎麼分層、錯誤怎麼回、日誌怎麼寫，先照你自己的判斷做。

## 動手之前

先寫下你打算做什麼：功能範圍、資料表、API 端點、錯誤分類。一頁就夠。檢查會談從這頁開始談。

## 流程

1. 你說完成之後約時間，一起看程式碼與錯誤邏輯
2. 依會談結果修正
3. 破壞測試：指導員製造故障，你只看日誌，時限內指出錯誤碼與原因

會談的方向：

- 分層：東西為什麼放在這一層，換一層會怎樣
- 錯誤處理：哪些錯誤被忽略了，為什麼可以忽略
- 錯誤碼：每個碼為什麼存在，拿掉會有哪個分支就此沉默
- 日誌：出事的時候這幾行夠不夠用
- 設定與版本：這台機器上跑的是哪一版，設定從哪來

團隊在這幾件事上有固定的做法，會談時會講。跟你做的不一樣的地方就是修正清單。

修正完成後才派 02。
