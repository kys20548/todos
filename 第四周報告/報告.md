# 第四周報告

## 總覽

在 devbox 架設 Gitea（內部 git 伺服器），與 PostgreSQL 放在同一份 compose：`deploy/db/docker-compose.yaml`。Gitea 用內建 SQLite，資料放在 `gitea_data` volume。

| 項目 | 設定 |
|---|---|
| image | `gitea/gitea:1.22` |
| 資料庫 | SQLite（`/data/gitea/gitea.db`） |
| 網頁 | 3000 |
| SSH | 222（devbox 自己的 sshd 佔 22） |

## 一、部署

devbox 沒有外網，image 在本機 pull 後離線載入。

本機：

```bash
docker pull gitea/gitea:1.22
docker save -o dist/gitea-image.tar gitea/gitea:1.22
scp dist/gitea-image.tar deploy/db/docker-compose.yaml .env.example devbox:~/
```

devbox：

```bash
docker load -i gitea-image.tar
docker compose config
docker compose up -d
```

## 二、測試

本機開通道，瀏覽器開 `http://localhost:3000`：

```bash
ssh -N -L 3000:localhost:3000 devbox
```

安裝精靈保持預設（資料庫 SQLite3），建立管理員帳號。

## 三、push / pull 測試

1. 在 Gitea 建立 repo（例如 `testRepo`）。
2. 把本機公鑰（`~/.ssh/id_ed25519.pub`）加進 Gitea：頭像 → 設定 → SSH / GPG 金鑰。
3. clone、push：

```bash
git clone ssh://git@10.140.0.29:222/danny/testRepo.git
```

devbox 要經 jump 才連得到，本機 `.ssh/config` 需要：

```
Host jump
    HostName 35.201.136.42
    User danny

Host 10.140.0.29
    ProxyJump jump
```

沒加金鑰會出現 `Permission denied (publickey)`。

## 四、對外開放：jump 上架 nginx 轉發

管理員在 jump 開了外網的 3000（網頁）和 222（git SSH）。devbox 在內網，所以由 jump 的 nginx 轉發到 devbox（`10.140.0.29`）。

```
外網 ──3000──▶ jump nginx ──▶ devbox:3000（Gitea 網頁）
外網 ──222───▶ jump nginx ──▶ devbox:222 （Gitea git SSH）
```

### 設定

- `nginx.conf`（repo 根目錄）：3000 用 `http` 區塊做反向代理；222 是純 TCP，要用 `stream` 區塊，不能放在 `http` 裡。
- `docker-compose.yaml`（jump）新增 `gitea-proxy` 服務，用 `nginx:alpine`，直接 pull。

```yaml
gitea-proxy:
  image: nginx:alpine
  restart: unless-stopped
  ports:
    - "3000:3000"
    - "222:222"
  volumes:
    - ./nginx.conf:/etc/nginx/nginx.conf:ro
```

部署到 jump（`nginx.conf` 要和 compose 同一個資料夾）：

```bash
scp docker-compose.yaml nginx.conf jump:~/todoapp/
ssh jump "cd ~/todoapp && docker compose up -d gitea-proxy"
```

devbox 的 `.env` 改成對外位址，Gitea 顯示的 clone 網址才會正確，改完 `docker compose up -d`：

```
GITEA_DOMAIN=35.201.136.42
GITEA_ROOT_URL=http://35.201.136.42:3000/
```

### 碰到的問題：rootless docker 不能綁 222

`docker compose up -d` 時 `gitea-proxy` 起不來：

```
cannot expose privileged port 222, you can add 'net.ipv4.ip_unprivileged_port_start=222' to /etc/sysctl.conf (currently 1024) ... bind: permission denied
```

原因：jump 用 rootless docker（第三周），一般使用者預設不能綁 1024 以下的 port。這正是第三周提到的 rootless 代價之一。3000 大於 1024，所以沒問題。

解法：把一般使用者可綁的最低 port 調到 222。設 222 而不是 0，範圍盡量小，22 仍然只有 root 能綁。

```bash
echo 'net.ipv4.ip_unprivileged_port_start=222' | sudo tee /etc/sysctl.d/99-rootless-port.conf
sudo sysctl --system
docker compose up -d
```

替代方案：請管理員改開 1024 以上的 port（例如 2222），compose 改成 `"2222:222"`，`GITEA_SSH_PORT` 同步改。

### 測試

jump 本機（nginx 有沒有轉發到 devbox）：

```bash
curl -sI http://localhost:3000 | head -3
ssh -T -p 222 git@localhost
```

本機（外網是否通）：

```bash
curl -sI http://35.201.136.42:3000 | head -3
ssh -T -p 222 git@35.201.136.42
git clone ssh://git@35.201.136.42:222/danny/testRepo.git
```

- `timed out`：防火牆沒開。
- `502`：jump 連不到 devbox，檢查 devbox 防火牆是否允許 jump 連 3000、222。
- `Permission denied (publickey)`：連線已通，只是金鑰沒加進 Gitea。

### 補充

- **公開 repo 的 HTTP clone 不需要帳密**：`testRepo` 是 public，匿名可 clone；push 或私有 repo 才需要驗證。若要全部登入才能看，設 `GITEA__service__REQUIRE_SIGNIN_VIEW: "true"`。
- **HTTP 是明文**：登入密碼會明文走過外網，內部使用建議以 SSH 為主。
- **為什麼不用路徑（`/gitea`、`/ssh`）分流**：路徑只有 HTTP 有，HTTP 可用 `location /gitea/` 轉發（但 Gitea 的 `ROOT_URL` 也要改成子路徑）；SSH 沒有路徑概念，只能靠 port 區分。
- **80 port**：外網防火牆預設沒開（`ncat` 測試 timeout），且 rootless 綁 80 要把 sysctl 調得更低，因此維持 3000。
